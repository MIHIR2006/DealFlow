# DealFlow360 — Backend

Go + Gin + PostgreSQL API for the DealFlow360 sales operations platform.

## Quick start

```bash
cp .env.example .env      # then fill in DATABASE_URL and JWT_SECRET
make run
curl localhost:8080/healthz
```

`make help` lists every target. `make ci` runs exactly what the pipeline runs.

## Layout

```
cmd/server              API entrypoint
cmd/seed                demo dataset loader (Phase 2)

internal/domain         PURE business engines — no DB, no HTTP, no globals
  money                 decimal helpers + the rounding policy
  pricing               line totals, effective discount, margin
  risk                  blended score + approval routing
  fulfillment           warehouse split + backorders
  billing               proration + recurring schedules

internal/db             goose migrations, sqlc query sources, generated code
internal/service        orchestration, transactions, authorization
internal/transport/http router, middleware, DTOs
internal/platform       config, db pool, logger, cache, error taxonomy
```

## The one rule

`internal/domain` may import **only the standard library and
`shopspring/decimal`**. No pgx, no Gin, no other internal package.

That keeps the business logic unit-testable in milliseconds, lets several
people work in parallel before the schema exists, and means the rules the
problem statement grades can never be "faked for the demo".

`make arch` enforces this and runs in CI.

## Conventions

**Money.** `shopspring/decimal` in Go, `NUMERIC(14,2)` for amounts and
`NUMERIC(6,3)` for percentages in Postgres. `float64` anywhere near money is a
review failure. Round half-up at the line level; order totals are the sum of
already-rounded lines, never a rounded sum.

**Errors.** Return `*apierr.Error` from services. Handlers call
`http.Fail(c, err)`. Every response uses the frozen envelope, which the
frontend switches on:

```json
{"error":{"code":"VALIDATION_FAILED","message":"...","details":{}}}
```

Codes: `UNAUTHENTICATED` `FORBIDDEN` `NOT_FOUND` `VALIDATION_FAILED`
`CONFLICT` `RATE_LIMITED` `INTERNAL`. Untyped errors collapse to `INTERNAL`
so internals never reach a client.

**Pagination.** Every list endpoint returns `http.Page[T]`
(`{"data":[...],"next_cursor":"..."}`) and accepts `?limit=&cursor=`.
No unbounded queries, from day one.

**Queries.** Written by hand in `internal/db/queries`, typed code generated by
sqlc. Nested reads are two queries and an in-memory join
(`WHERE parent_id = ANY($1::bigint[])`), never a query inside a loop.
Aggregates are `GROUP BY` in SQL, never summed in Go.

**Logging.** `logger.From(ctx)` inside a request — the returned logger already
carries `request_id`, method and path.

**Probes.** `/healthz` is liveness and never touches the database.
`/readyz` is readiness and does.

## Config

Every variable is loaded and validated at boot by `internal/platform/config`.
Missing or malformed values stop the process with a message listing *all*
problems at once. Nothing else in the codebase calls `os.Getenv`.

See `.env.example`.
